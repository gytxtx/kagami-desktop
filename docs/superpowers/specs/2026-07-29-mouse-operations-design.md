# 完整鼠标操作设计

## 背景

Kagami 已支持带目标校验的物理单击，但缺少双击、指针移动、滚轮与拖拽，无法覆盖常见的真实桌面操作。新增能力必须延续物理输入安全契约，避免事件被投递到错误窗口。

## 目标

- 提供独立、可组合的 `move`、`double-click`、`scroll` 与 `drag` 命令。
- 所有鼠标输入均绑定目标窗口，并在执行前验证前台状态与窗口族命中关系。
- 让调用方从结构化响应中得知实际完成的手势与坐标。

## 非目标

- 不提供任意鼠标脚本或多步骤宏。
- 不改变现有 `click` 命令的参数和行为。
- 不新增自动激活窗口的隐式副作用。

## 命令契约

### `move`

```
move --hwnd X --x X --y Y [--expected-state guard-uuid.json]
```

移动鼠标指针至屏幕物理坐标，不发送按键事件。

### `double-click`

```
double-click --hwnd X --x X --y Y [--right] [--expected-state guard-uuid.json]
```

在同一坐标连续发送两次完整的按下和释放；默认左键，`--right` 表示右键双击。

### `scroll`

```
scroll --hwnd X --x X --y Y --delta D [--expected-state guard-uuid.json]
```

先将指针移动到目标坐标，再发送垂直滚轮事件。正 `delta` 向上滚动，负值向下滚动；有效范围为 `-17895697..17895697` 且不能为零。超出范围的值无法安全换算为 Win32 的 120 单位、32 位有符号滚轮数据，应在注入前以 `INVALID_ARGUMENT` 拒绝。

### `drag`

```
drag --hwnd X --from-x X --from-y Y --to-x X --to-y Y [--expected-state guard-uuid.json]
```

在起点移动、左键按下、移动到终点并释放左键。起点和终点都必须命中目标窗口族；若任一校验失败，操作开始前拒绝，保证不会留下按下状态。

## 安全与错误处理

四个命令均要求提供 `--hwnd` 或经验证的 `--expected-state`；二者同时提供时必须指向同一窗口。执行前复用既有校验：目标窗口存在、身份未变、位于前台，且操作坐标命中该窗口族。

`drag` 使用起点校验取得的目标身份，再额外校验终点，之后才注入任何输入。输入 API 返回不完整事件数时，返回既有注入失败错误；对于已经发送按下的异常路径，尽力发送释放事件后再失败，降低卡住鼠标键的风险。

## 输出与测试

每个命令返回其语义、实际执行路径、目标 HWND 和坐标；滚轮额外返回 delta，拖拽返回起点与终点。`capabilities` 的 `mouse_commands` 数组列出 `move`、`double-click`、`scroll` 与 `drag`，供调用方进行机器可读的能力协商。

测试覆盖 CLI 参数绑定、正确事件序列、零滚轮 delta 与换算溢出拒绝、前台拒绝、起点/终点命中拒绝、capabilities 命令清单及结构化响应。README、`docs/DESIGN.md` 与能力输出同步记录新命令。

## 验收标准

在目标窗口前台且坐标命中时，四个命令均生成预期的 Win32 `SendInput` 事件；任意失焦、guard 失效或坐标命中其他窗口时，均在生成输入前失败。现有 `click`、`key` 和文本输入行为保持不变。
